# Роадмап до alpha и публикации

Режим проекта: сначала пет, архитектура с запасом на рост ([DESIGN.md](DESIGN.md)). Сроков нет,
размер задач указан относительно: S — вечер, M — несколько вечеров, L — неделя и больше.
Каждая фаза заканчивается проверяемым критерием выхода.

## Фаза 0 — замеры и фиксация формата

Цель: не строить кодоген поверх формата, который потом придётся менять.

| # | Задача | Размер |
|---|---|---|
| 0.1 | Перевести репо в монорепо (pnpm workspaces): `packages/`, `bench/`, `spikes/`, `docs/`, CI на GitHub Actions | S |
| 0.2 | Браузерный бенч: Playwright, Chromium, Firefox, WebKit, те же сценарии S1–S4 + `memo`, отчёт в Markdown | M |
| 0.3 | Цена vtable: геттер через vtable против фиксированного смещения, Node и три браузера | S |
| 0.4 | Сжатие: 5 кандидатов из DESIGN §11 на gzip-6, brotli-4/6/11, zstd-3, набор payload’ов (CRUD, телеметрия, вложенные) | M |
| 0.5 | Строки: порог ASCII-цикла против `TextDecoder` по браузерам, Latin-1/UTF-16 по флагу против UTF-8 | S |
| 0.6 | Бенч realtime-режима: 1–100 сущностей × 20–60 Гц, накладные расходы на сообщение | S |
| 0.7 | Написать `docs/FORMAT.md` v0 по итогам 0.3–0.5 | M |

**Выход:** `FORMAT.md` зафиксирован, у каждого решения в нём есть цифра из бенча. Если цели паритета
по сжатию нет, JSON-режим переезжает из «бета» в alpha.

## Публикация alpha

- [ ] Финальное имя. `ts-bin-rpc` на npm свободно, `tbr` занято (как имя бинаря внутри пакета допустимо).
- [ ] Лицензия (MIT), `package.json`: только ESM, `exports` с подпутями, `sideEffects: false`, `engines`.
- [ ] Публикация из GitHub Actions с `--provenance`, версия `0.1.0-alpha.0`, dist-tag `alpha`.
- [ ] CHANGELOG, политика версий: до 1.0 формат может меняться, но версия формата в заголовке и `check`
      предупреждают об этом.
- [ ] Сделать репозиторий публичным (сейчас приватный). Перед этим проверить историю на внутренние ссылки.
- [ ] Заметка о безопасности: что верифицируется, что нет, как сообщать об уязвимостях.

## После alpha (ориентир, не план)

Порядок определяет обратная связь. Кандидаты:
1. Адаптер TanStack Query (`queryOptions` из клиента, материализация через `toPlain` на границе кэша).
2. Стриминг: async iterator в хендлере → поток сообщений; WebSocket-транспорт со смешанными кадрами,
   snapshot + delta для колонок, кольцевые буферы.
3. Мидлвары поверх `ctx` (auth, логирование, бизнес-валидация — бывший `extendValidation`).
4. Vite-плагин: кодоген в dev-сервере, шаг генерации не виден.
5. `Map`, `Record`, кортежи, struct-раскладка, квантование (`f32` → `i16` с масштабом).
6. Эксперимент с адаптерами к tRPC и oRPC.
7. Бенчи против Arrow JS / Flechette и Colyseus, импорт и экспорт Arrow IPC.
8. Батчинг, GET-кэширование, WebTransport.
